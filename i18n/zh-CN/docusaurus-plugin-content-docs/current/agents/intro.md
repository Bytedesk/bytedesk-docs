# 微语 AI 智能体

微语 AI 智能体是面向客户全生命周期规划的数字化团队成员。它把全渠道会话、知识库问答、工作流自动化、CRM 客户画像、订单数据、工单与数据分析连接起来，让企业把每一次服务对话沉淀为可复用的客户资产。

当前 Agent 文档用于说明产品方向与后续实现规划，部分能力会随着 AI、工作流、渠道、工单和运营模块逐步完善并分阶段上线。

## 智能体矩阵

- [客服助手 Agent](./customer-service-assistant.md)：辅助人工客服完成回复建议、知识检索、会话小结、质检提醒和下一步动作推荐。
- [售前 Agent](./pre-sales-agent.md)：识别访客意图，推荐商品或方案，收集线索，并引导访客完成转化。
- [售中 Agent](./sales-agent.md)：支持报价、下单引导、支付提醒、履约咨询，以及服务系统与业务系统之间的协同。
- [售后 Agent](./after-sales-agent.md)：处理订单、物流、退款、退换货、质保、投诉和工单跟进等场景。
- [语音服务 Agent](./voice-service-agent.md)：把呼入接待、语音 IVR、报修受理、预约确认、工单派发、服务回访和客诉预警串成服务履约闭环。
- [运营 Agent](./operations-agent.md)：把服务数据转化为用户分群、活动触达、复购运营和增长分析。

## 产品理念

微语将 AI Agent 定位为能够执行业务动作的数字员工，而不是简单的聊天机器人。长期架构围绕一个闭环展开：

1. 会话产生结构化客户数据。
2. 客户数据沉淀为画像、标签、意图和服务历史。
3. 智能体基于上下文提供个性化服务，并触发自动化流程。
4. 运营团队复盘效果，持续优化知识、流程、转化与留存。

通过这个闭环，客服不再只是成本中心：客服助手降低人工负担，售前提升转化，售中保障成交，售后守住满意度，运营把每次互动变成可复用的增长洞察。

## 服务闭环设计

智能体系统不能停留在“回答问题”。真实服务工作的难点，是整条链路不能断：客户来电后，系统要识别意图、采集必要字段、创建工单、完成派单、跟踪履约、确认结果，并把风险信号反馈给运营和管理者。

微语围绕这个闭环设计 Agent 时遵循四个原则：

1. 优先选择目标清晰、流程可拆、结果可验的场景，例如报修受理、报装预约、进度确认、满意度回访和客诉回访。
2. 将自然对话转化为结构化业务数据，包括客户身份、地址、设备、订单、问题分类、紧急程度、预约时间、凭证和期望结果。
3. 将 Agent 接入可执行系统，包括 CRM、订单、工单、工作流、通话记录、录音、ASR 转写、知识库和通知渠道。
4. 持续运营 Agent，重点观察转人工率、完成率、Bad Case、打断节点、缺失字段、客户反馈和人工复盘结果。

在这个模型中，Agent 是服务流程里的数字执行单元。它的价值不只是和客户对话，而是帮助企业看见、推进并持续优化完整服务过程。
