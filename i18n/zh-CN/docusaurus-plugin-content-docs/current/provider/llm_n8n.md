# 对接 N8N

本页说明 n8n 在微语中的当前集成定位。

## 概览

当前仓库已经明确把 n8n 视为一个受支持的第三方集成选项：

- n8n 已出现在后台内置 provider 列表中
- provider 元数据中包含生产 base URL 与官网地址
- 租户与组织级配置项中已经存在 n8n 记录，并与 MaxKB 等第三方 provider 并列

这说明 n8n 在微语里主要被视为外部自动化与工作流编排目标。

## n8n 适合的场景

在微语中，n8n 更适合承担以下类型的工作：

- 将 AI 与客服事件对接到外部自动化流程
- 把结构化数据路由到第三方系统
- 在微语核心运行时之外触发自定义业务自动化
- 对接 CRM、通知、审批流或 Webhook 型逻辑

## 当前可确认的集成证据

目前仓库中可以明确确认：

- 已存在 `n8n` provider 元数据
- 已在第三方 provider 列表中展示与分类
- SQL 初始化数据中已为 n8n 预置相关设置记录

这些证据足以说明 n8n 是一个受支持的 provider 选项，但还不足以在本页中宣称存在固定且完整的 API 合约，因此本页保持保守描述。

## 推荐接入路径

建议采用以下集成方式：

1. 准备一个 n8n 实例并发布目标工作流入口
2. 在微语中配置对应的 n8n provider 项
3. 将该 provider 绑定到需要的业务流、机器人或外部回调场景
4. 用真实工作流执行结果验证返回 payload 结构是否符合调用方预期

## 运维建议

- 尽量保持工作流入口稳定并做版本化
- 在接入生产流量前，先校验 webhook 鉴权与密钥配置
- 确保返回结构与调用方流程预期一致
