# 对话工作流

微语对话工作流（Chat Flow）可以理解为一套“可视化对话脚本”：

- 你不用写代码，只需要在 ChatBuilder 里拖拽节点
- 系统会按你设计的路径，自动引导访客完成咨询、分流、留资、转人工等动作
- 适合售前咨询、售后分诊、活动报名、线索收集等场景

一句话：把“客服每次都要重复问的话”，变成一条可复用、可优化、可统计的自动流程。

![chat_flow](/img/chat_flow/chat_flow.png)

## 适合谁用

- 运营：想把咨询入口标准化，提升转化率
- 客服主管：想减少重复问答，提升接待效率
- 业务负责人：想快速上线一个可控的自动对话流程

## 能解决什么问题

- **回复不一致**：不同客服说法不统一，用户体验不稳定
- **人工压力大**：大量重复问题占用客服时间
- **线索质量参差**：缺少标准化信息收集，转化跟进困难
- **转人工时机不明确**：用户该分给谁、何时分流不清楚

## ChatBuilder 是什么

ChatBuilder 是对话流程的可视化编辑器。你可以把它理解成“流程图搭建工具”：

- 左侧是可拖拽节点
- 中间是流程画布
- 右侧是节点配置（标题、文案、选项、条件等）

你搭好的流程可以直接用于访客侧会话，支持先测试再发布。

## 常用节点（非技术版）

下面是最常用的几类节点，用业务语言理解即可：

- **开始节点**：流程入口（系统自动带一个）
- **文本节点**：发送一句提示或说明
- **问题节点**：向访客提问并记录答案（如“请问您的城市是？”）
- **选择节点**：给访客多个按钮选项（如“售前咨询 / 售后服务”）
- **条件节点**：根据访客选择或答案分支到不同路径
- **表单节点**：收集结构化信息（姓名、电话、需求描述等）
- **HTTP 节点**：连接外部系统（CRM、订单、活动系统等）
- **结束节点**：结束当前流程

## 一个典型流程长什么样

示例：售前咨询自动分流

1. 文本节点：欢迎语 + 服务承诺
2. 选择节点：咨询类型（产品咨询 / 价格咨询 / 合作咨询）
3. 条件节点：按类型分支
4. 表单节点：收集联系方式与需求
5. 文本节点：告知处理时效
6. 结束节点或转人工

这个结构的价值是：用户体验统一、线索信息完整、人工介入更精准。

## 从 0 到 1 搭建步骤

1. **先定目标**
	这条流程是为了“分流”“留资”还是“减少人工”？一次只解决一个核心目标。
2. **画出最短路径**
	先做最小可用版本（MVP），不要一开始就把流程做得很复杂。
3. **设置关键节点**
	至少包含：开场文案、一个选择节点、一个表单节点、一个结束动作。
4. **补充异常分支**
	例如用户不想填表、信息不完整、超时未回复时怎么处理。
5. **先测试再发布**
	用测试会话完整走一遍，确认每条分支都能走通。
6. **观察数据并迭代**
	重点看：完成率、放弃点、转人工率、有效线索率。

## 写文案的实用建议

- 一句话只表达一个动作，避免长段落
- 用“下一步指令”引导用户，比如“请先选择您的问题类型”
- 表单字段控制在 3-5 个，先收关键项，减少流失
- 对用户有成本的动作（填手机号）要说明价值（“便于客服 10 分钟内联系您”）

## 上线前检查清单

- 每个选择项都连接了后续节点
- 表单必填项合理，不会过多
- 条件分支有兜底路径（避免“走不下去”）
- 转人工策略明确（什么时候转、转给谁）
- 关键提示文案已校对（品牌语气、时效承诺）

## 常见问题

### 1）流程很长，用户中途容易流失怎么办？

先压缩成 3-5 步主链路，把复杂问题放到转人工后处理。优先保证“先完成，再完善”。

### 2）选择节点和表单节点先放哪个？

多数场景建议“先选择再表单”。先分流到正确路径，再收集针对性信息，填写意愿更高。

### 3）什么时候需要用 HTTP 节点？

当你希望自动查询外部数据或把结果回写到业务系统时使用。比如查询订单状态、写入 CRM 线索。

### 4）如何判断流程是否有效？

至少观察这 4 个指标：流程完成率、有效线索率、转人工率、平均处理时长。连续 1-2 周优化一次效果最好。

## 推荐落地节奏

- 第 1 周：先上线 1 条“高频场景”流程（例如售前咨询）
- 第 2 周：根据放弃点优化文案与字段
- 第 3 周：增加 1 条分支或接入外部系统
- 第 4 周：形成标准模板，复制到其他业务线

如果你刚开始使用，建议先做一个“欢迎语 + 选择节点 + 表单节点 + 转人工”的基础版流程，最快当天就能上线并看到效果。
