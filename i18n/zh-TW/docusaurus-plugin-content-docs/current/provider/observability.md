# 可觀測性

微語已經具備一定的可觀測性基礎，用於追蹤系統執行狀態、記錄執行軌跡、分析服務效能，並為問題定位與生產維運提供支撐。對於持續擴展中的 AI 工作流、多模態處理與自動化能力來說，可觀測性會越來越重要。

## 一、目前已有的可觀測性基礎

從目前倉庫與介面定義可以看到，微語已包含：

- Trace 管理相關介面
- Server Metrics 管理相關介面
- 支援查詢、匯出與分析的執行資料能力
- 與監控、指標相關的模型欄位與 OpenAPI 定義

這說明可觀測性在微語中已具備基礎平台能力，而不只是未來規劃項。

## 二、可觀測性涵蓋什麼內容

微語目前可觀測性的重點主要包括：

- 追蹤執行鏈路與請求軌跡
- 監控伺服器效能與資源使用情況
- 支撐問題排查與維運複盤
- 為 AI 驅動場景提供更清晰的執行視角

## 三、為什麼它重要

隨著微語逐步引入更多 AI 能力，可觀測性對以下場景特別關鍵：

- 排查模型驅動工作流的問題
- 識別服務效能瓶頸與延遲來源
- 回看執行歷史與系統行為
- 為生產級維運、穩定性治理與品質保障提供依據

## 四、與其它能力頁的關係

- [工具](./tools) 關注可執行的呼叫能力。
- [MCP](./mcp) 關注協議層互通。
- [文本模型指南](./model_text) 及相關模型頁關注模型配置本身，而可觀測性幫助團隊理解這些模型與流程在執行時的實際表現。

## 五、總結

可觀測性為微語提供了執行可見性層。當前系統中已存在 traces、metrics 與可匯出的執行資料，這為穩定的客服系統執行，以及未來更複雜 AI 能力的可靠性治理提供了重要基礎。
