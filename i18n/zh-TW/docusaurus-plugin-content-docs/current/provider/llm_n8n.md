# LLM N8N

本頁說明 n8n 在微語中的目前接入定位。

## 概述

目前倉庫已顯示 n8n 被視為受支援的第三方整合選項：

- n8n 已出現在管理端資產中的內建 provider 清單
- provider 元資料包含正式 base URL 與官網資訊
- 租戶與組織層級設定中已有 n8n 預置項，並與 MaxKB 等第三方提供商並列

這表示 n8n 在 provider 體系中主要被定位為外部自動化與工作流整合目標。

## n8n 適合的場景

在微語裡，n8n 更適合被理解為工作流編排端點，可用於：

- 把 AI 與客服事件接到外部自動化流程
- 將結構化資料路由到第三方系統
- 在微語核心執行時之外觸發自定義業務自動化
- 整合 CRM、通知、審批流或 webhook 邏輯

## 目前可確認的接入依據

目前程式碼可確認：

- 內建的 `n8n` provider 元資料
- 在第三方提供商清單中的顯示與分類
- SQL 初始化資料中已存在 n8n 設定記錄

這已足夠將 n8n 文檔化為支援中的 provider 選項，但還不足以在本頁宣稱固定且完整的 API 契約。

## 建議的接入方向

較穩妥的接入模式是：

1. 準備 n8n 實例並發佈目標工作流端點
2. 在微語中配置對應的 n8n provider 項
3. 把它綁定到需要的業務流、機器人或外部回調場景
4. 以真實工作流執行測試返回資料結構

## 運維注意事項

- 盡量保持端點穩定並做好版本管理
- 啟用生產流量前先驗證 webhook 驗證與密鑰
- 確認返回結構符合調用方預期
