# 語音助手

語音助手是微語面向訪客提供的一種自然互動方式。訪客不需要反覆打字，可以直接按住說話，也可以切換成文字輸入，系統會理解訪客的問題，並用簡潔、適合播報的方式給出回答。

對企業來說，它可以作為官網諮詢、產品導覽、服務分流、活動答疑、售前接待等場景中的第一層智慧接待入口，讓使用者更快開口、讓服務更自然。

:::tip 提示
語音助手依賴企業版 AI、語音辨識和語音合成能力。社群版預設不支援，如需使用請先確認授權與相關設定已經開通。
:::

## 它能做什麼

### 1. 訪客可以直接開口諮詢

進入語音助手頁面後，訪客可以使用兩種方式發起提問：

- 文字輸入：適合安靜環境、需要精確輸入的場景
- 按住說話：適合行動端、雙手不方便、想更自然表達的場景

系統會自動辨識訪客說的話，並把核心內容整理成可理解的問題。

### 2. 系統會自動生成適合語音播報的回答

語音助手不是單純把長篇文字念出來，而是會優先生成更自然、更口語化的回答。當前實作會盡量控制回覆長度，讓結果更適合直接播放給訪客收聽。

這代表它更像一位「會說話的智慧接待員」，而不是一個只會朗讀文本的機器人。

### 3. 支援自動語音回播

在預設情況下，系統會把回答自動播放給訪客。對訪客來說，體驗更接近真實對話：

- 說出問題
- 系統理解問題
- 返回文字回答
- 同時自動播報回答內容

如果不方便播放聲音，也可以關閉播放，只查看文字結果。

### 4. 支援連續多輪交流

語音助手不是一次性問答。訪客可以持續提問，系統會在當前會話上下文裡繼續理解問題，形成更接近「對話」的交流體驗。

### 5. 資訊不足時會先追問

如果訪客表達得不完整，系統不會急著給出模糊答案，而是會先禮貌追問關鍵缺失資訊。例如只問「今天天氣怎麼樣」，系統會繼續詢問具體城市或地區，再給出更有針對性的回覆。

從頁面體驗來看，語音助手盡量保持簡潔，重點突出「馬上開口」和「快速得到回覆」。

頁面中通常包含以下幾個核心區域：

- 頂部狀態區：顯示當前助手狀態，例如準備中、正在聆聽、正在處理、連線異常等
- 對話訊息區：展示訪客問題和助手回覆，方便回看上下文
- 底部控制區：支援在「語音輸入」和「文字輸入」之間切換
- 錄音回饋區：在說話時顯示錄音狀態、音量回饋和錄音時長

這套設計對非技術使用者的意義很明確：不需要學習複雜操作，只需要像使用語音留言一樣按住說話即可。

## 一次完整對話是怎麼完成的

從業務角度理解，語音助手的一次互動大致分為四步：

1. 訪客透過按住說話或文字輸入表達問題。
2. 系統先理解訪客內容，語音輸入會自動轉成文字。
3. AI 根據問題生成一段簡潔自然的回覆。
4. 系統把回覆顯示在頁面上，並可自動播報給訪客。

因此，它同時打通了「聽懂使用者」和「開口回答」兩件事。

## 適合哪些業務場景

### 官網諮詢接待

適合放在企業官網、品牌官網、產品官網中，作為訪客的第一接待入口。使用者不用找表單、不用思考怎麼打字，直接開口就能問。

### 售前導購與產品答疑

適合處理高頻、重複、標準化的問題，例如：

- 產品價格怎麼收費
- 功能是否支援某種場景
- 如何預約示範
- 是否支援客製化或串接

### 服務入口分流

訪客先透過語音表達訴求，系統先進行初步理解，再決定是繼續自助回覆，還是再引導到人工客服、留資、工單或其他流程。

### 行動端與無障礙場景

在手機端、走路中、開車場景或不方便打字的情況下，語音助手比傳統文字會話更自然，也更容易提升互動率。

## 它帶來的業務價值

### 提高訪客發起諮詢的意願

很多使用者不是沒有問題，而是不願意打字。語音入口降低了表達門檻，通常更容易觸發首次諮詢。

### 縮短回應路徑

訪客可以更快描述問題，系統也能立即給出答覆，減少等待和來回確認成本。

### 讓智慧客服更有人感

相比純文字機器人，語音助手的互動更像真實交流，尤其適合品牌想要增強服務溫度和體驗差異化的場景。

### 為人工客服減壓

高頻、標準化、可複用的問題可以先由語音助手承接，把人工客服資源留給更複雜、更高價值的問題。

## 當前能力邊界

語音助手已經具備完整的語音問答體驗，但它的定位仍然是「智慧接待與答疑助手」，不是一個可以隨意承諾業務結果的人工代理。當前實作中有幾個非常重要的邊界：

- 回覆會優先追求自然、簡潔、適合播報
- 當資訊不足時，會先追問關鍵內容
- 不應編造訂單、帳號、庫存、工單狀態或系統內不存在的資料
- 更適合承接諮詢、說明、引導、答疑類場景

如果企業希望它回答更準確、更貼近業務，需要進一步結合知識庫、業務規則、介面資料或人工轉接流程。

## 使用時需要注意

### 1. 瀏覽器需要麥克風權限

如果訪客沒有授權麥克風，就無法使用按住說話功能，但仍可以切換到文字輸入模式繼續使用。

### 2. 錄音不能太短

當前體驗中，如果錄音過短或沒有偵測到有效語音，系統會直接提醒使用者重新說一遍，而不是生成錯誤答案。

### 3. 建議在安靜環境下使用

雖然系統會盡量辨識語音內容，但在嘈雜環境、遠距離收音、弱網或麥克風品質較差時，辨識效果和整體體驗可能會受到影響。

### 4. 建議優先處理高頻標準問題

如果問題需要依賴企業內部即時資料，建議把語音助手作為前置接待入口，而不是直接讓它獨立處理最終業務結果。

## 推薦的落地方式

對大多數企業來說，語音助手最適合這樣使用：

- 第一步：先承接官網或落地頁的高頻諮詢
- 第二步：把常見問答整理成標準口徑
- 第三步：對複雜問題引導轉人工或轉其他業務流程
- 第四步：根據真實諮詢記錄持續優化話術和知識內容

這樣上線風險更低，見效也更快。

## 總結

微語語音助手可以理解為一個可說、可聽、可繼續追問的智慧接待入口。它把語音輸入、AI 理解、自動回覆和語音播報連接成一條完整鏈路，讓訪客與系統的互動從「打字問答」升級為更自然的「開口交流」。

如果你的業務希望降低諮詢門檻、提升行動端體驗、增強智慧接待的親和力，語音助手會是一個很適合落地的能力模組。
