# 限制成員登入平台

限制成員登入平台，是一項面向管理員的帳號權限控制功能。

它的作用是：控制某個成員帳號可以登入哪些系統後台，不能登入哪些系統後台。

你可以把它理解為：

- 這個成員能進入哪些工作台
- 這個成員不能進入哪些後台
- 不同崗位，只開放對應的平台入口

例如：

- 普通客服，只允許登入客服工作台
- 知識庫維護人員，只允許登入知識庫後台
- 工作流設定人員，只允許登入工作流後台
- 組織管理員，可以登入全部平台

## 可以限制哪些平台

系統支援按成員維度控制以下平台的登入權限：

- 管理後台 admin
- 客服工作台 desktop
- 知識庫後台 notebase
- 工作流後台 workflow
- 呼叫中心工作台 call
- 呼叫中心管理後台 callAdmin

管理員可以根據崗位需要，為每個成員勾選允許登入的平台。

## 適合什麼場景

這個功能通常適用於以下場景：

- 同一個組織內有不同崗位，不希望所有人都能進入所有後台
- 只允許客服進入客服工作台，不允許進入管理後台
- 只允許營運或知識庫編輯人員進入知識庫後台
- 只允許指定人員進入工作流或呼叫中心相關後台
- 新成員剛加入時，只開放最基礎的登入入口
- 人員崗位發生變化時，及時調整其可存取的平台範圍

## 預設規則

為了便於使用，系統預設按角色提供基礎權限：

- 組織管理員或超級管理員：預設可登入所有平台
- 其他普通成員：預設只允許登入客服工作台 desktop

這意味著：

- 管理員通常不需要額外逐個平台勾選
- 普通成員如果需要進入更多後台，需要管理員額外授權

## 設定後會發生什麼

當管理員儲存成員的「可登入平台」設定後，系統會依照這個設定控制該成員後續登入。

如果成員去登入一個未被允許的平台：

- 系統會跳出提示，說明目前帳號沒有該平台的登入權限
- 使用者確認後，將無法繼續進入該平台
- 已有的帳號、成員資料、歷史資料不會被刪除

如果成員登入的是被允許的平台：

- 可以正常進入並使用對應系統

## 如何理解這個功能

對於非技術使用者，可以把它理解為「按崗位分配入口」。

它不是刪除帳號，也不是停用成員，而是控制「這個人可以從哪個門進去」。

所以它和刪除、停用、強制下線的差別是：

- 限制登入平台：控制能登入哪個平台
- 強制下線：立即停止繼續使用某個平台
- 刪除成員：移除成員資料和組織關係

如果你只是想控制成員存取範圍，通常優先使用「限制登入平台」。

## 常見使用示例

### 示例一：普通客服

如果某位成員只是負責接待訪客，建議只保留：

- 客服工作台 desktop

這樣可以避免其誤進入管理後台、知識庫後台或工作流後台。

### 示例二：知識庫維護人員

如果某位成員主要維護知識庫內容，可以只保留：

- 知識庫後台 notebase

如同時需要處理客服會話，也可以再增加：

- 客服工作台 desktop

### 示例三：組織管理員

如果某位成員是組織管理員，通常需要處理設定、人員、知識庫、流程等多個模組，建議保留全部平台權限。

系統預設也會為管理員開放全部平台。

## 使用建議

為了減少誤操作和權限過大，建議按以下原則設定：

- 按崗位開放，而不是一次性開放全部平台
- 普通成員優先只給必要平台
- 管理員或負責人再開放更多平台
- 人員轉崗後，及時調整可登入平台
- 定期檢查成員權限，避免歷史遺留帳號擁有過多入口

## 總結

限制成員登入平台的核心作用，是幫助管理員按崗位更精細地控制系統入口。

它可以讓不同成員只進入自己需要使用的後台，既方便管理，也能降低誤操作和越權存取的風險。

如果你希望做到「同一個帳號，不同崗位只能進入不同平台」，那麼這個功能就是最直接、最好理解的方式。
