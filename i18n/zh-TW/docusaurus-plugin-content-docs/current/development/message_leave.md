# 留言處理

## 概述

當客服離線時，系統可以自動顯示留言表單，讓訪客提交需求與聯絡方式，而不是直接流失。透過 Webhook 通知與結構化處理流程，團隊即使在非即時服務時段，也能持續處理客戶需求。

### 主要功能特性

- 客服離線時自動收集留言
- 支援以已發佈表單 schema 動態渲染自訂留言表單
- 支援企業微信、飛書、釘釘等多種通知方式
- 支援圖片上傳，便於更完整描述問題
- 支援透過備援客服、備援工作組等方式承接離線需求
- 訪客可查看歷史留言與回覆紀錄
- 客服端可即時處理與跟進留言

### 使用場景

- 下班時間或節假日的離線支援
- 客服高峰期，暫時無法即時回覆
- 需要先蒐集結構化資訊再做後續處理的場景
- 跨時區服務運營

### 自訂留言表單

管理員可以在後台為留言場景綁定「自訂表單」。啟用後，訪客端不再只顯示固定的預設欄位，而是依照已發佈表單的 schema 動態渲染輸入項。

典型配置步驟如下：

1. 在 FormBuilder 中建立一個類型為 `MESSAGE_LEAVE` 的表單。
2. 發佈表單。
3. 在留言設定中開啟「啟用留言表單」。
4. 如需使用自訂欄位，再開啟「使用自訂表單」，並選擇剛發佈的表單。

建議至少保留以下關鍵資訊：

- 聯絡人姓名
- 至少一種有效聯絡方式
- 留言內容或問題描述
- 問題類型、來源、優先級等業務欄位

### 留言開關行為說明

留言相關開關會直接影響訪客端展示邏輯：

- 開啟「啟用留言表單」後，訪客在離線留言場景中可以直接填寫並提交留言。
- 關閉「啟用留言表單」後，訪客端不再顯示留言表單與相關快捷入口。
- 開啟「使用自訂表單」且已選擇有效表單後，訪客看到的是自訂欄位，而不是只有預設欄位。
- 如果自訂表單未啟用、未發佈或無效，系統會回退到預設留言表單。

### 自訂欄位保存說明

提交流程會優先提取並保存標準欄位，例如姓名、聯絡方式、問題類型、留言內容與圖片附件。

- 標準欄位會以結構化資料形式保存，便於後續篩選與處理。
- 其他自訂欄位則會隨留言內容一起保存，方便客服在上下文中查看。

## 客服端功能

![leavemsg_agent](/img/develop/leavemsg/leavemsg_agent.png)

客服端通常支援：

- 待處理留言列表
- 查看訪客提交的完整資訊
- 回覆與跟進處理
- 更新狀態，例如待處理、已回覆、已關閉
- 必要時轉交或重新分派

### 留言處理流程

1. 系統收到新的留言。
2. 對應團隊收到通知。
3. 客服查看提交內容。
4. 客服進行回覆或跟進。
5. 更新留言狀態並持續追蹤。

## 管理後台功能

![leavemsg_admin](/img/develop/leavemsg/leavemsg_admin.png)

管理後台提供集中式留言管理能力，包括：

- 留言數量與處理統計
- 依類型、狀態、時間等維度篩選
- 批次操作與資料匯出
- 不同角色的權限控制

### 留言設定配置項

在服務設定中，團隊可以配置：

- 展示給訪客的留言提示語
- 是否啟用留言表單
- 是否使用自訂留言表單
- 綁定哪一個自訂表單
- 備援客服設定
- 備援工作組設定

典型的離線承接優先順序為：

1. 備援客服
2. 備援工作組
3. 機器人或其他預設離線處理邏輯

如果前一個環節已經可以承接，後面的環節就不會再啟用。

## 最佳實踐

### 留言表單設計

1. 簡化必填欄位，只保留真正必要的資訊。
2. 使用分類欄位支援後續分流。
3. 提供清楚的填寫提示與說明。
4. 對敏感資訊說明用途，降低顧慮。

### 回覆策略

1. 為所有留言設定明確的回覆時限。
2. 能個人化回覆時，避免過度模板化。
3. 為複雜問題設計跟進規則。
4. 在需要時持續收集訪客滿意度。

### 資料分析

1. 追蹤留言數量與類型的變化趨勢。
2. 監控處理效率與回覆品質。
3. 識別高頻問題並優化服務流程。
4. 用結果反向優化表單與整體客服流程。

## 常見問題

**Q: 如何設定留言自動通知？**
A: 在管理後台配置 Webhook 通知目標，並綁定到支援的通知渠道。之後新留言即可自動推送。

**Q: 訪客可以刪除已提交的留言嗎？**
A: 目前訪客無法直接刪除已提交留言。如需刪除，需由客服或管理員處理。

**Q: 留言資料會長期保存嗎？**
A: 留言紀錄通常會保存在後台，方便團隊做歷史查看、後續跟進與資料匯出。

**Q: 是否支援多語言留言流程？**
A: 支援。Bytedesk 提供多語言介面能力，留言體驗也可以作為整體服務流程的一部分進行在地化。
