# PopUp

來電彈屏是微語呼叫中心在坐席工作台中的即時電話提醒能力。當客戶透過手機、固話或外部線路呼入，系統會在坐席工作台自動彈出通話視窗，顯示來電號碼、通話狀態與坐席操作入口，幫助客服第一時間識別客戶並快速接聽。

![客服端來電彈屏示範](/img/callcenter/popup/popup.png)

## 功能亮點

- **即時來電提醒**：客戶呼入並分配到坐席分機後，坐席工作台會自動彈出來電視窗，坐席無需切換頁面即可看到來電。
- **號碼資訊顯示**：彈屏顯示主叫號碼或 SIP 對端資訊，後續可結合客戶資料、訪客檔案、工單與歷史會話持續擴充顯示內容。
- **一鍵接聽與拒接**：坐席工作台軟電話在線時，坐席可直接在彈屏中接聽或拒接來電。
- **通話中狀態顯示**：接聽後自動切換為通話視窗，顯示通話狀態、通話時長、靜音、掛斷等操作。
- **固定話機協同**：同一個分機可同時綁定固定話機與坐席工作台。固定話機響鈴時，坐席工作台同步彈屏；固定話機摘機後，坐席工作台同步顯示通話中；固定話機掛機後，坐席工作台同步恢復空閒。
- **呼入 IVR 聯動**：客戶先進入 IVR 語音導航，按鍵轉人工後，來電仍可繼續觸發坐席彈屏。

## 典型使用流程

1. 管理員為坐席配置呼叫參數，例如綁定分機 `5003` 並啟用呼叫功能。
2. 坐席打開坐席工作台，在軟電話工具列中點擊「簽入」。
3. 客戶撥打企業電話，呼叫進入 FreeSWITCH、IVR 或佇列流程。
4. 當呼叫轉接到坐席分機時，坐席工作台收到來電事件並彈出來電視窗。
5. 坐席可以在坐席工作台上接聽，也可以透過綁定的固定話機摘機接聽。
6. 通話建立後，坐席工作台自動顯示通話中、通話時長等狀態。
7. 任一終端掛機後，坐席工作台同步顯示通話結束。

## 彈屏內容

目前坐席工作台彈屏主要包含以下資訊與操作：

- 來電號碼或 SIP 對端標識。
- 來電狀態，例如響鈴中、通話中、固定話機通話中、通話結束。
- 接聽、拒接、掛斷、靜音等軟電話操作。
- 通話時長。
- 外部終端接聽提示，例如「目前由固定話機通話，坐席工作台僅同步顯示狀態」。

在實際業務場景中，還可以進一步把來電號碼與客戶資料打通，在彈屏中顯示客戶姓名、歸屬地、最近會話、歷史工單、訂單資訊、服務標籤與備註等。

## 固定話機與坐席工作台共號

微語支援固定話機與坐席工作台共用同一個坐席分機。例如固定話機綁定 `5003`，坐席工作台目前登入坐席也簽入 `5003`。

這種模式適合以下場景：

- 客服習慣使用固定話機接聽電話，但仍希望坐席工作台自動彈出客戶資料。
- 坐席需要在電腦上查看客戶資訊、建立工單、記錄備註，同時用固定話機保持穩定通話。
- 企業希望逐步從傳統話機遷移到 WebRTC 軟電話，但保留兩種接聽方式。

共號模式下，系統透過 FreeSWITCH 多註冊能力保留固定話機與坐席工作台的不同 Contact。坐席工作台註冊時會使用獨立的 SIP 實例標識，簽出時只註銷自己的 WebRTC 註冊，不影響固定話機註冊。這樣可以實現：

- 坐席工作台未簽入：固定話機仍可正常響鈴。
- 坐席工作台已簽入：固定話機響鈴，同時坐席工作台來電彈屏。
- 固定話機接聽：坐席工作台同步顯示通話中，並停用不適用於外部終端通話的本地控制。
- 固定話機掛機：坐席工作台同步顯示通話結束。

## 實現原理

來電彈屏由 FreeSWITCH 呼叫事件、後端 ESL 事件流與坐席工作台 SIP 控制器共同完成。

### 後端事件流

FreeSWITCH 呼叫過程中會產生 `CHANNEL_CREATE`、`CHANNEL_ANSWER`、`CHANNEL_HANGUP`、`CHANNEL_CALLSTATE` 等事件。微語後端監聽這些事件並發布為統一的呼叫事件，再透過 SSE 推送給坐席工作台。

### 坐席工作台彈屏

坐席工作台使用 SIP.js 註冊坐席分機，並透過帶鑑權請求標頭的 SSE 訂閱後端 ESL 事件流。收到與目前分機匹配的事件後，前端會把 FreeSWITCH 事件映射為來電狀態：

- `CHANNEL_CREATE`：響鈴中，打開來電彈屏。
- `CHANNEL_ANSWER`：通話中。
- `CHANNEL_HANGUP` / `CHANNEL_HANGUP_COMPLETE` / `CHANNEL_DESTROY`：通話結束。
- `CHANNEL_CALLSTATE` / `CHANNEL_STATE`：補充識別響鈴、接聽、掛斷等狀態。

### IVR 轉人工彈屏

當客戶先進入 IVR，再按鍵轉人工時，鏈路通常是：

1. 外線號碼進入 FreeSWITCH。
2. 撥號計畫把呼叫轉入 IVR 入口，例如 `5002`。
3. IVR 透過 HTTAPI 播放歡迎語並收集按鍵。
4. 客戶按 `0` 後，系統執行 `transfer 5003 XML default` 轉入人工坐席分機。
5. `5003` 的固定話機與坐席工作台註冊終端同時被呼叫。
6. 坐席工作台收到呼叫事件並彈屏。

這種方式不會繞過 FreeSWITCH 的 dialplan 與 directory，因此可以繼續使用固定話機註冊、坐席工作台 WebRTC 註冊、多終端共振與狀態同步能力。

## 配置要求

使用來電彈屏前，需要確認以下配置已完成：

- FreeSWITCH 已啟用，且微語後端已開啟 `bytedesk.call.freeswitch.enabled=true`。
- 坐席工作台目前登入帳號具備坐席身份。
- 坐席已配置並啟用 `CallSettingsEntity`，其中目標分機與 FreeSWITCH 分機一致。
- 坐席工作台可以存取 SIP WebSocket 服務，並能成功註冊分機。
- 後端 `/api/v1/freeswitch/esl/events/stream` 可被坐席工作台存取，且請求攜帶有效登入令牌。
- 固定話機與坐席工作台共號時，FreeSWITCH 需要允許同一分機多 Contact 註冊。

## 排查建議

如果沒有彈屏或狀態不同步，可以按以下順序排查：

1. 在坐席工作台軟電話工具列確認坐席是否已簽入，SIP 註冊狀態是否成功。
2. 在 FreeSWITCH 中檢查分機是否已註冊，例如查看 `show registrations`。
3. 呼叫後端 `/api/v1/freeswitch/esl/events/recent`，確認是否能看到 `CHANNEL_CREATE`、`CHANNEL_ANSWER`、`CHANNEL_HANGUP` 等事件。
4. 確認坐席工作台能正常存取 `/api/v1/freeswitch/esl/events/stream`，且沒有鑑權失敗。
5. 如果固定話機響鈴但坐席工作台不彈屏，重點檢查 ESL 事件流與坐席工作台簽入狀態。
6. 如果坐席工作台彈屏但固定話機不響鈴，重點檢查 FreeSWITCH 分機註冊、directory `dial-string` 與多註冊配置。
7. 如果固定話機接聽後坐席工作台不顯示通話中，重點檢查 `CHANNEL_ANSWER` 事件是否包含目前分機號或 Presence ID。

## 適用場景

- 企業服務熱線呼入，客服接聽前自動識別客戶。
- IVR 按鍵轉人工後自動彈屏。
- 固定話機接聽，坐席工作台同步顯示客戶資訊與通話狀態。
- 電話客服與線上客服統一工作台，邊通話邊記錄工單、備註與會話內容。
- 呼叫中心坐席進行外呼、保持、轉接、轉 IVR 等電話操作。
