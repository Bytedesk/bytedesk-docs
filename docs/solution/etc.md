# ETC行业智能客服解决方案

## 1. 需求说明（基于你提供的截图整理）

ETC智能客服不是单点问答，而是“多角色协同”的服务体系。核心诉求包括：

- 多渠道统一接入：网站、APP、小程序、公众号、企微等
- 智能分流与转人工：按规则自动分配，复杂问题可快速升级
- 工单闭环：从建单、分单、催办到回访全流程可追踪
- 运营可视化：主管可看实时指标、质检结果和趋势报表

## 2. 按角色看需求（简单版）

### 2.1 客服人员（一线执行）

- 需要统一工作台：会话、客户信息、知识库、工单同屏处理
- 常见问题由机器人先答，复杂问题一键转人工
- 支持快捷回复、敏感词提醒、会话标签和历史记录查看

### 2.2 资源处理专员（工单处理）

- 关注工单时效：新单提醒、超时预警、催办机制
- 支持跨部门协作：可转派、可升级、可回退
- 处理结果可回传会话侧，避免重复沟通

### 2.3 客服主管/运营经理

- 关注分配效率：排队时长、接入速度、转人工成功率
- 关注服务质量：满意度、首次解决率、投诉率
- 关注运营看板：按日/周/月查看趋势，支持团队对比

### 2.4 质检与培训人员

- 需要会话抽检与规则质检（服务规范、话术完整性、风险用语）
- 支持问题归因与培训闭环（从“发现问题”到“改进知识库/话术”）

### 2.5 ETC用户与ETC商户

- 用户关注：办理、激活、扣费、发票、退款、投诉处理进度
- 商户关注：对账、批量开票、异常账单、服务时效

## 3. 核心业务场景

### 3.1 办理与激活

- 智能引导办理材料、步骤和入口
- 激活失败自动给出排查路径（设备、网络、绑定信息）

### 3.2 扣费争议与通行记录

- 支持按车牌、时间、路段查询通行与扣费信息
- 对重复扣费、异常扣费提供标准解释与申诉入口

### 3.3 工单与回访

- 会话中一键建单，自动带入用户资料与上下文
- 处理完毕后自动触发回访，沉淀满意度数据

### 3.4 高峰与应急

- 节假日高峰由机器人优先承接高频咨询
- 系统异常、舆情投诉等场景可启用应急话术和优先级策略

## 4. 关键流程（用户视角）

1. 用户咨询：例如“今天为什么被扣了两次费？”
2. AI初判：识别意图，优先命中知识库并给出处理建议。
3. 自动分流：可解答问题由机器人闭环，复杂问题转人工/建工单。
4. 协同处理：专员处理后回传结果，必要时升级或跨部门流转。
5. 结果通知：将处理进度和最终结果反馈给用户并收集满意度。

## 5. 指标建议（便于验收）

可按以下口径设定阶段目标：

- 首次响应时长：不超过5秒
- 工单按时处理率：不低于98%
- 会话满意度：不低于90%
- 机器人独立解决率：首期不低于30%，成熟期不低于50%
- 转人工成功率：不低于90%

## 6. 需求到微语能力映射

| 需求方向 | 微语能力 | 交付结果 |
| --- | --- | --- |
| 多渠道统一接入 | 网站/APP/微信/企微等渠道接入 | 用户咨询入口统一 |
| 智能分流 | AI意图识别 + 路由规则 + 技能组分配 | 减少排队与错分 |
| 智能转人工 | 保留上下文、携带客户信息、会话不中断 | 提升一次解决率 |
| 工单闭环 | 会话建单、SLA预警、流转与回访 | 问题处理可追踪 |
| 运营看板 | 会话、工单、满意度、质检报表 | 管理决策数据化 |
| 质检培训 | 规则质检 + 典型案例沉淀 + 知识库优化 | 持续提升服务质量 |

## 7. 分阶段落地建议

### 第一阶段（1-2周）：先跑通

- 上线高频FAQ（办理、激活、扣费、发票、退款）
- 打通1-2个主渠道，配置机器人与转人工规则

### 第二阶段（2-4周）：做闭环

- 对接通行记录、账单、发票等业务系统
- 上线工单流转、SLA告警、满意度回收

### 第三阶段（持续）：做优化

- 以数据驱动优化知识库和路由策略
- 对高投诉场景做专项治理，提升机器人独立解决率

## 8. 预期价值

- 服务更快：高峰期也能稳定接待
- 服务更准：统一口径，减少误答和重复沟通
- 管理更清晰：从会话到工单全流程可视、可追踪、可复盘
